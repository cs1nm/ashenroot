# Shadowgrove — мультиплеер

## Режимы

Сетевая архитектура сохраняет одиночную игру и добавляет ENet-сессии:

- обычная офлайн-игра;
- listen-server из Android/desktop-клиента;
- выделенный headless-сервер на Windows/Linux/VPS;
- подключение через интернет по IP или без интернета через хот-спот;
- до 8 игроков;
- переключаемые владельцем PvE/PvP;
- пароль сервера;
- автоматическая передача сжатого мира при подключении.

ENet использует **UDP**. Для интернет-сервера нужно открыть выбранный UDP-порт в роутере и firewall (по умолчанию `24567`). У мобильных операторов часто используется CGNAT, поэтому сервер на Android обычно доступен через хот-спот, но не из интернета. Для постоянного интернет-сервера надёжнее ПК/VPS с публичным адресом.

## Сервер из игры

1. Создай и хотя бы один раз открой одиночный мир.
2. На главном экране нажми **MULTIPLAYER**.
3. Выбери мир, имя сервера, UDP-порт и при необходимости пароль.
4. Выбери PvE/PvP и нажми **HOST WORLD**.
5. Остальные игроки вводят IP, порт и пароль через **JOIN IP**.

Для игры без интернета включи хот-спот на телефоне, подключи к нему остальные устройства и используй локальный IP хоста. Поиск серверов в локальной сети не используется.

Владелец может переключать PvE/PvP во время игры из меню паузы. Там же отображаются участники, их пинг, кнопки **KICK**/**BAN** для каждого гостя, сетевой чат, **FORCE SAVE**, **CLEAR BANS** и **COPY HOST IP**. Бан привязан к постоянному профилю устройства и сохраняется между перезапусками сервера. Обычная кнопка **TO MENU** сначала сохраняет мир, уведомляет гостей и только потом останавливает listen-server. Союзники отмечаются цветными точками на миникарте и полной карте.

У формы прямого подключения есть меню **RECENT** с восемью последними адресами и портами. История хранится локально; пароль в неё не попадает.

## Выделенный сервер

Проект можно запустить в Godot 4.7.1 без графики:

```bash
Godot_v4.7.1-stable_linux.x86_64 \
  --headless --path /path/to/ashenroot -- \
  --dedicated \
  --world=0 \
  --port=24567 \
  --name="My Shadowgrove" \
  --password="optional-password" \
  --pvp=false \
  --admin=/path/admin_commands.txt
```

Также есть оболочки `server/start_server.sh` и `server/start_server.bat`. Путь к Godot задаётся переменной `GODOT_BIN`.

Аргументы после второго `--`:

- `--world=N` — слот серверного мира, по умолчанию `0`;
- `--port=N` — UDP-порт, по умолчанию `24567`;
- `--name=TEXT` — имя сервера;
- `--password=TEXT` — необязательный пароль;
- `--pvp=true|false` — режим PvP;
- `--import=/path/world.json` — проверить и импортировать мир перед запуском;
- `--export=/path/world.json` — обновлять внешнюю копию мира при автосохранении;
- `--admin=/path/admin_commands.txt` — раз в секунду принимать административные команды из файла.

Успешный запуск выводит:

```text
DEDICATED_SERVER_READY port=24567 world=0 mode=pve
```

### Администрирование dedicated server

`server/start_server.sh` и `.bat` автоматически подключают файл `server/admin_commands.txt`. Запиши в него одну или несколько команд — сервер выполнит их и очистит файл:

```text
STATUS
SAVE
KICK 12345678
BAN 12345678
CLEAR_BANS
SHUTDOWN Плановый перезапуск
```

- `STATUS` печатает roster, количество банов и сетевые метрики;
- `SAVE` принудительно сохраняет мир и обновляет `--export`;
- `KICK` отключает указанный peer id;
- `BAN` сохраняет профиль в `user://server_bans.json` и отключает его;
- `CLEAR_BANS` очищает persistent ban-list;
- `SHUTDOWN` сохраняет мир, доставляет причину клиентам, ждёт отключения и штатно завершает процесс.

Подключения, входы, отказы, отключения и действия администратора пишутся JSON-строками в `user://server_connections.log`; при 2 MiB журнал ротируется в `.1`. Пароли не логируются.

### Готовые Windows/Linux-пакеты

Воспроизводимая сборка пакетов с закреплённым Godot 4.7.1:

```bash
GODOT_BIN=/path/Godot_v4.7.1-stable_linux.x86_64 \
  tools/package_dedicated.sh
```

Скрипт скачивает официальный Windows runtime (если `GODOT_WINDOWS_BIN` не задан), делает общий `.pck`, создаёт Linux `tar.gz`, Windows `.zip`, manifests и `SHA256SUMS.txt` в `dist/dedicated`. Внутри архивов уже есть runtime, launchers и `admin.sh`/`admin.bat`; отдельная установка Godot не нужна.

## Импорт и экспорт мира

Кнопка **EXPORT** на сетевом экране копирует выбранный мир в Downloads как `shadowgrove_world_N.json`, если платформа разрешает запись, иначе используется `user://exports`.

Выделенный сервер принимает этот файл через `--import`. Параметр `--export` создаёт обновляемую копию. После остановки сервера положи её в Downloads под тем же именем, выбери исходный слот в игре и нажми **IMPORT**. Нельзя заменять сейв во время работы сервера; перед импортом в клиенте нужно отключиться от сети.

## Модель авторитета

- Сервер управляет врагами, их здоровьем, снарядами и общим состоянием мира.
- Клиент предсказывает своё движение и отправляет ограниченный по частоте state stream.
- Положение других игроков сглаживается между пакетами.
- Враги выбирают ближайшего подключённого игрока, а спавны распределяются между участниками.
- Добыча и установка блоков выполняются сервером с проверкой расстояния, инструмента и ресурсов.
- Общий лут, крафт, расходники и содержимое сундуков изменяются только сервером.
- Открытый сундук обновляется у всех игроков, которые одновременно его просматривают.
- Сервер проверяет экипировку, допустимый урон, снаряды и PvP-удары.
- Здоровье, смерть, возрождение и восстановление гостя подтверждаются сервером.
- Атмосферную погоду, её таймер и интенсивность выбирает сервер; клиенты получают состояние в entity snapshots. Сервер применяет погоду к зрению AI, а каждый клиент рассчитывает локальное воздействие на температуру, слышимость шагов и статусы по общей синхронизированной погоде.
- Карта поверхностных биомов приходит вместе с миром. Метаданные плавных границ и шум перехода детерминированно пересоздаются из seed на каждом клиенте, поэтому для них не нужны отдельные RPC или дополнительные поля сейва.
- Handshake проверяет версию протокола, пароль, лимит игроков, имена и постоянный идентификатор профиля.

## Профили гостей

При первой сетевой игре устройство создаёт локальный случайный идентификатор. В каждом мире хоста по нему сохраняются инвентарь, панель быстрого доступа, экипировка, класс, здоровье, позиция и точка возрождения гостя. Поэтому повторное подключение с того же устройства продолжает предыдущий прогресс, даже если игрок поменял отображаемое имя.

Профили входят в сейв мира и в `--export`. Переустановка игры или очистка её данных создаст новый идентификатор и новый профиль. Одновременное подключение одного профиля с двух копий клиента запрещено.

Перед перезаписью активного мира игра автоматически создаёт резервную копию в `user://backups/world_N`. Копии создаются не чаще раза в пять минут, для каждого мира сохраняются последние пять файлов. Это работает и для listen-server, и для dedicated server.

Клиент измеряет задержку раз в две секунды и показывает `GOOD`, `FAIR`, `POOR` либо `UNSTABLE`. Подключение имеет 12-секундный тайм-аут, а пропавший сервер автоматически возвращает клиента в главное меню.

Протокол версии 5 передаёт entity snapshots как `var_to_bytes` + FastLZ вместо полного Variant RPC. Движение жидкостей тоже авторитетно: сервер симулирует активные области возле всех участников, отправляет надёжные FastLZ-пакеты компактных состояний `[x, y, tile, level]`, а новый клиент получает актуальные уровни заполнения вместе со снимком мира. Сервер каждые 30 секунд и при завершении печатает `[network] diagnostics/...`: число подключений, state-пакетов, snapshots, raw/compressed bytes, compression ratio, пакеты/состояния жидкостей, оценки entity/liquid bytes и принятые либо ограниченные действия.

Автоматические проверки нового контура:

```bash
# Сохранение, подземное затухание и snapshot-поля погоды
Godot --headless --path . --script res://tests/weather_smoke_test.gd

# Частичное заполнение, объём, затухание движения, save/load и сетевой runtime sync
Godot --headless --path . --script res://tests/world_generation_smoke_test.gd
GODOT_BIN=/path/godot tools/run_network_liquid_smoke.sh

# 4–8 лёгких клиентов: движение, actions, chat, latency и reconnect
GODOT_BIN=/path/godot BOT_COUNT=8 DURATION=45 tools/run_network_stress.sh

# persistent BAN, повторный отказ, журнал, CLEAR_BANS, SAVE, SHUTDOWN
GODOT_BIN=/path/godot tools/run_network_admin_smoke.sh
```

Публичный браузер серверов пока отложен. Для него потребуется отдельно развёрнутый HTTPS master-server; прямое подключение и хот-спот от него не зависят.
